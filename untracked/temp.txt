

The normal Lava Protocol flow (what's running now):


lavap rpcconsumer pod       lavap provider pod         Real blockchain node
(receives HTTP from        (acts as gRPC bridge)       (Google, QuickNode)
 your tests)
      │                           │                           │
      │──── gRPC RelayRequest ───▶│                           │
      │     (relay.proto)         │──── HTTP JSON-RPC ───────▶│
      │                           │◀─── HTTP response ────────│
      │◀─── gRPC RelayReply ──────│

The chains[].providers[].endpoints[].url in values.yml is the HTTP URL that the lavap provider pod connects to.
The consumer and provider pods always talk gRPC to each other.

Option A — HTTP simulator in lava-infra

lavap rpcconsumer pod       lavap provider pod         HTTP simulator pod

      │                           │                      lava-infra)
      │──── gRPC RelayRequest ───▶│                           │
      │                           │──── HTTP JSON-RPC ───────▶│
      │                           │◀─── fake response ────────│
      │◀─── gRPC RelayReply ──────│


Option B — static-providers with gRPC simulator

static-providers is a lavap rpcconsumer flag that tells the consumer: skip the Lava blockchain entirely, connect
directly to these hardcoded gRPC addresses. No lavap provider pods needed at all — the consumer talks gRPC directly
to whatever is at those addresses.

lavap rpcconsumer pod       provider_simulator pod
(static-providers mode)     (gRPC, relay.proto — the
                             EXISTING provider_simulator
      │                      in your project)
      │──── gRPC RelayRequest (relay.proto) ───────────────▶│
      │◀─── gRPC RelayReply ───────────────────────────────│
